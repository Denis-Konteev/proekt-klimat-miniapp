## Что это за проект

Telegram Mini App для канала «PROEKT KLIMAT UZ Инженерия» (t.me/proektklimatuz).

Стек:
- **Фронтенд**: React + Vite, репозиторий `ProektKlimatUz/proekt-klimat-miniapp`
  на GitHub, деплой на Vercel → `https://proekt-klimat-miniapp.vercel.app`
- **Бэкенд**: n8n на PikaPods (`nifty-beluga.pikapod.net`), воркфлоу «Profile API»
  (эндпоинты `get-profile` GET и `save-profile` POST) и «Checkin API»
- **База данных**: Supabase, проект `ProektKlimatUz`, таблицы `users` и `events`.
  Фото хранится как base64-текст прямо в колонке `users.photo_path` (Storage
  bucket создан, но не используется)
- Все данные Telegram (initData) проверяются на сервере через HMAC-подпись —
  устройство пользователя не может подделать telegram_id

## Текущий статус: НЕ ЗАВЕРШЕНО — один незакрытый баг верификации

**Симптом:** после заполнения формы профиля (ФИО, должность, компания, фото)
и нажатия «Сохранить и верифицировать», бейдж в интерфейсе показывает
«Не верифицировано», хотя сохранение реально прошло успешно.

**Подтверждено РАБОЧИМ (не тратить время на перепроверку этого):**
1. n8n workflow «Profile API», ветка POST (`save-profile`) — реально пишет
   `is_verified: true` в Supabase. Подтверждено дважды через Output ноды
   `Update a row`.
2. Сама таблица Supabase `users` — подтверждено напрямую через Table Editor:
   для `telegram_id = 658738765` прямо сейчас `is_verified = TRUE`, все поля
   (`real_first_name`, `real_last_name`, `position`, `company`, `photo_path`)
   заполнены корректно.
3. `saveProfileToBackend()` во фронтенде (`src/App.jsx`, ищите по
   `function saveProfileToBackend`) — корректно разворачивает массив от
   Supabase-ноды `Update a row` (`Array.isArray(data) ? data[0] : data`).
4. `checkinToBackend()` — та же правка внесена и там (баллы за чек-ин).
5. `fetchProfile()` (ищите `function fetchProfile`) — на вид тоже полностью
   корректна: разворачивает массив от `Get a row`, читает `row.is_verified`.
6. Деплой на Vercel — подтверждено, что грузится самая свежая версия кода
   (кнопка «Купить Продвинутый» показывает честную «· СКОРО» вместо старого
   демо-переключателя — этот текст появился только в последней правке).
   `vercel.json` с `Cache-Control: no-cache` добавлен и подтверждён (200 OK).
   Кэш Telegram явно очищался через Настройки → Данные и память → Очистить
   кэш (не просто закрытие приложения).

**Что осталось непроверенным — точка входа для продолжения:**
Раз БД содержит `is_verified: true`, а код чтения выглядит правильным, но
интерфейс всё равно показывает «Не верифицировано» — проблема либо:
(a) в n8n workflow «Profile API», ветка **GET** (`get-profile`) — нода
`Get a row` или нода `Code in JavaScript` (HMAC-проверка) перед ней могут
возвращать не то, что ожидается;
(b) либо в самом моменте вызова `fetchProfile()` на фронтенде — стоит
проверить порядок `useEffect`, не вызывается ли что-то, что перезаписывает
`profile` уже ПОСЛЕ успешного `fetchProfile()`.

**Следующий конкретный шаг (с подключённым n8n-коннектором это можно
сделать без скриншотов):** посмотреть в n8n Executions самый свежий GET-запрос
(ветка `get-profile`) → нода `Get a row` → Output → проверить `is_verified`
для `telegram_id = 658738765`. Если там `false`/`null` — баг в чтении на
стороне n8n/Supabase. Если там `true` — баг чисто во фронтенде, искать через
`grep -n "setProfile("` все места записи состояния и порядок эффектов.

## Как продолжать работу с кодом
1. Скачать текущий `src/App.jsx` с GitHub
   (`raw.githubusercontent.com/ProektKlimatUz/proekt-klimat-miniapp/main/src/App.jsx`)
2. Внести правку локально и **пересобрать проект** (`npm install && npm run build`)
   — единственный надёжный способ убедиться, что правка не ломает синтаксис
3. Прислать готовый файл для замены на GitHub (Edit → выделить всё → вставить
   → Commit), дождаться статуса Ready на Vercel

## Известные особенности инфраструктуры (чтобы не наступать повторно)
- n8n на PikaPods запрещает `require('crypto')`-зависимые глобалы вроде
  `URLSearchParams` внутри Code-узлов — HMAC-проверка initData написана вручную
  (см. функцию `parseQueryString` в Code-узлах n8n)
- Supabase-ноды `Get a row`/`Update a row` в n8n ВСЕГДА возвращают МАССИВ
  (`[{...}]`), даже для одной строки — фронтенд обязан разворачивать его
- Кнопка Redeploy в Vercel пересобирает ТОТ ЖЕ коммит, на котором её нажали —
  не подтягивает новые изменения с GitHub. Нужен новый commit, не Redeploy
- Хэш имени JS-файла сборки (`index-XXXXXXXX.js`) иногда совпадает между
  разными версиями по совпадению — это НЕ признак того, что деплой не
  обновился (проверено независимой пересборкой и содержимым бандла)
- Telegram агрессивно кэширует WebView-ресурсы; обычное закрытие приложения
  НЕ чистит этот кэш — нужна явная «Очистить кэш Telegram» в настройках
